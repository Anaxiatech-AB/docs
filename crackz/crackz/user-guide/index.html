    User Guide¶

    A comprehensive guide to using Crackz for AI-powered crack detection and infrastructure inspection.

    1. Overview¶

    Crackz is an AI-driven image analysis tool designed for detecting cracks in harbor infrastructure, bridges, and industrial facilities. It provides:

    • Automated crack detection using deep learning segmentation models
    • Flexible workflows via CLI and GUI interfaces
    • Structured project management with train/val/test/raw data splits
    • Reproducible results through configuration snapshots
    • Scalable deployment options (local, Docker, Azure Batch)
    • Open architecture supporting multiple model types and encoders

    Model Capabilities¶

    Segmentation Models (Default) - Binary segmentation: Pixel-level crack/no-crack or deviation/no-deviation mapping - Multi-class segmentation: Detect multiple defect types (cracks, corrosion, spalling) - Encoder flexibility: Choose from 20+ backbones (ResNet, EfficientNet, MobileNet, etc.) - Transfer learning: Leverage ImageNet pre-trained weights or train from scratch

    Classification Models (Future Extension) - Whole-image analysis: Quick assessment ("has crack" vs "no crack") - Triage workflows: Filter large image sets before detailed segmentation - Edge deployment: Lightweight models for mobile devices

    Two Deployment Paths¶

    Path 1: Train Custom Model - Import labeled training data (images with ground truth masks) - Configure model architecture and hyperparameters - Train model via crackz detect train - Best for: Domain-specific data, unique defect types, custom requirements

    Path 2: Use Pre-Trained Model - Acquire ready-made checkpoint from model providers or previous projects - Place checkpoint in project artifacts directory - Run detection immediately with crackz detect run - Best for: Quick deployment, standard use cases, proof-of-concept, multi-site consistency

    High-Level Workflow¶

    graph LR
    A[Create Project] --> B[Import Images]
    B --> C{Need Custom Model?}
    C -->|Yes| D[Train Model]
    C -->|No| E[Run Detection]
    D --> E
    E --> F[View Results]
    F --> G{Satisfied?}
    G -->|No| H[Adjust Config]
    H --> D
    G -->|Yes| I[Export/Package]

    Typical Timeline: - Initial setup: 5-10 minutes - Training (light): 5-30 minutes depending on dataset size and hardware - Detection: Seconds to minutes per image - Full workflow (first run): 30-60 minutes

    2. Prerequisites¶

    Required¶

    • Python 3.11 – 3.13 (64-bit)
    • Operating System: Linux, macOS, or Windows 10/11
    • Disk Space: ~2-3 GB for PyTorch and model weights

    Optional¶

    • NVIDIA GPU: CUDA-capable GPU with 4+ GB VRAM for accelerated training/detection
    • Docker: For containerized deployments

    GPU Considerations¶

    Task CPU Performance GPU Benefit
    Detection (single image) 2-5 seconds 10-50x faster
    Training (small dataset, 10 epochs) 20-60 minutes 5-20x faster
    Batch detection (100 images) Minutes to hours Highly recommended

    GPU Driver Requirements: - CUDA 11.8 or 12.1+ recommended - Driver version 520+ for CUDA 12.x - Verify: nvidia-smi should show your GPU

    3. Installation¶

    See the detailed Installation guide for complete instructions. Quick reference:

    Standard CPU Install¶

    # Install from GitHub Release (replace VERSION with actual version)
pip install https://github.com/Anaxiatech-AB/crackz/releases/download/vVERSION/crackz-VERSION-py3-none-any.whl

# Or download first, then install
wget https://github.com/Anaxiatech-AB/crackz/releases/download/v0.30.2/crackz-0.30.2-py3-none-any.whl
pip install crackz-0.30.2-py3-none-any.whl

# Verify installation
crackz --help

    GPU Install¶

    # Install PyTorch with CUDA support first
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121

# Then install Crackz from GitHub Release
pip install https://github.com/Anaxiatech-AB/crackz/releases/download/vVERSION/crackz-VERSION-py3-none-any.whl

    Docker (No Python Required)¶

    # CPU version
docker pull ghcr.io/anaxiatech-ab/crackz:latest

# GPU version (requires nvidia-docker)
docker pull ghcr.io/anaxiatech-ab/crackz:gpu

# Slim version (minimal runtime)
docker pull ghcr.io/anaxiatech-ab/crackz:slim

    Registry URL: https://github.com/Anaxiatech-AB?tab=packages&repo_name=crackz

    Verify Installation: 

    crackz --version
python -c "import crackz; print('Crackz installed successfully')"

    4. Quick Start¶

    Complete end-to-end workflow in under 10 minutes:

    Step 1: Initialize a Project¶

    crackz init --name my-first-project
cd my-first-project

    This creates the following structure: 

    my-first-project/
├── images/          # Image storage by split
│   ├── raw/         # Unprocessed images for inference
│   ├── train/       # Training images
│   ├── val/         # Validation images
│   └── test/        # Test images
├── masks/           # Ground truth masks (optional for raw)
│   ├── train/
│   ├── val/
│   └── test/
├── artifacts/       # Model outputs (metrics, plots)
├── detections/      # Detection results (annotated images, JSON)
├── models/          # Saved model weights (or checkpoints/ in older projects)
├── logs/            # Project-specific logs
└── project.yaml     # Project configuration

    Note: Older projects may use checkpoints/ instead of models/. Use crackz migrate --project <project> --migrate-files to upgrade to the new structure, or the GUI will prompt you automatically when opening the project.

    Step 2: Import Images¶

    # Import sample images for detection (no training)
crackz import-images \
  --project my-first-project \
  --src ./samples \
  --type raw \
  --size 512 512

    What happens: - Images resized to 512×512 pixels (preserving aspect ratio with padding) - Normalized and validated - Copied to images/raw/

    Step 3: Run Detection (Lite Mode)¶

    # Use pre-trained model
crackz detect run --project my-first-project

    Results appear in: - detections/ - Annotated images with highlighted cracks - artifacts/metrics.json - Detection statistics

    Step 4: (Optional) Train on Custom Data¶

    If you have labeled training data: 

    # Import training images with masks
crackz import-images \
  --project my-first-project \
  --src ./training-data/images \
  --src-masks ./training-data/masks \
  --type train \
  --size 512 512

# Quick training (1 epoch for testing)
crackz detect train --project my-first-project --epochs 1 --batch-size 2

    Step 5: View Results¶

    # Check detection outputs
ls my-first-project/detections/

# View metrics
cat my-first-project/artifacts/metrics.json

# Open annotated images
open my-first-project/detections/*.png  # macOS
xdg-open my-first-project/detections/*.png  # Linux

    5. Core Concepts¶

    5.1 Project Layout¶

    Project Directory Structure: - images/: Organized by split (raw/train/val/test) - Use raw/ for inference-only images - Use train/val/test/ for model development - masks/: Ground truth segmentation masks (required for train/val/test) - Must match image filenames exactly - Binary masks: 0 = background, 255 = crack - artifacts/: Training outputs (loss curves, metrics JSON) - detections/: Detection results with overlays - models/: Saved model weights (.ckpt files) [or checkpoints/ in older projects] - logs/: Project-specific log files - project.yaml: Configuration file (version-controlled)

    5.2 Data Splits Explained¶

    Split Purpose Masks Required? When to Use
    raw Production inference No Real-world images for detection
    train Model training Yes Learning crack patterns
    val Hyperparameter tuning Yes Model selection, early stopping
    test Final evaluation Yes Unbiased performance report

    Best Practices: - Never tune on test data (use validation instead) - Typical split ratios: 70% train, 15% val, 15% test - Minimum validation set: 10-20 images - Keep test set untouched until final evaluation

    5.3 Artifacts¶

    Generated outputs from training and detection:

    Training Artifacts: - metrics.json - Per-epoch loss, IoU, F1 scores - loss_curve.png - Training/validation loss visualization - confusion_matrix.png - Classification performance (if applicable)

    Detection Artifacts: - Annotated images in detections/ with crack overlays - metrics.json - Summary statistics (total cracks, coverage %) - Optional: Bounding box coordinates, crack area measurements

    5.4 Logging Model¶

    Crackz uses a hybrid two-tier logging system:

    Layer Location When Active Purpose
    Central System temp or CRACKZ_LOG_DIR Always Captures issues before/without project
    Project <project>/logs/ After project load Project-specific diagnostics

    Configuration: 

    # Set central log directory
export CRACKZ_LOG_DIR=~/crackz-logs

# Both central and project logs will be written
crackz detect run --project my-project

    Log Levels: - --debug: Verbose output (all operations) - Default: Info level (key events only) - --quiet: Minimal output (errors only)

    5.5 Schema Versioning¶

    Projects include a schema version for forward compatibility:

    schema_version: "1.0"
project:
  name: my-project
  # ... rest of config

    Migrating Old Projects: 

    crackz migrate --project old-project

    See Migration Guide for details.

    5.6 Model Selection & Configuration¶

    Crackz supports multiple model architectures to match different use cases.

    Choosing a Model Type

    Use Case Model Type Configuration
    Precise crack mapping Binary segmentation num_classes: 1 (default)
    Multiple defect types Multi-class segmentation num_classes: 3 (e.g., crack/corrosion/spalling)
    Quick screening Classification (future) Custom model class

    Encoder Selection

    The encoder is the backbone network that extracts features from images:

    Encoder Speed Accuracy Memory Use Case
    resnet34 Medium Good Medium Default - balanced performance
    efficientnet-b0 Slow Excellent High Maximum accuracy
    mobilenet_v2 Fast Fair Low Edge deployment, real-time
    resnet18 Fast Fair Low Rapid prototyping
    resnet50 Slow Excellent High Large datasets

    Configuration Example

    Edit <project>/<project>_project.yaml:

    ai:
  model:
    encoder: resnet34           # Choose encoder backbone
    encoder_weights: imagenet   # Use transfer learning (recommended)
    in_channels: 3              # RGB images (use 1 for grayscale)
    num_classes: 1              # Binary segmentation
    threshold: 0.5              # Detection sensitivity (0.3=more sensitive, 0.7=less)

  training:
    epochs: 20                  # Number of training iterations
    batch_size: 8               # Images per batch (reduce if out of memory)
    learning_rate: 0.001        # Optimizer learning rate

    Pre-Trained vs Custom Training

    Scenario Recommendation Checkpoint Source
    Standard concrete cracks Use pre-trained Acquire from model provider
    Harbor-specific patterns Train custom Import labeled harbor images
    Bridge multi-defect Pre-trained or fine-tune Start with general model, adapt
    Proof-of-concept Use pre-trained Quick deployment
    Production deployment Train custom Domain-specific data

    Acquiring Pre-Trained Models

    Pre-trained checkpoints can come from: 1. Model providers: Commercial or open-source model repositories 2. Previous projects: Reuse successful models across sites 3. Partners: Share validated models within organization 4. Transfer learning: Fine-tune from general-purpose checkpoint

    Importing Models:

    Use the model import command to add a pre-trained model to your project:

    crackz model import --project ./my_project --model pretrained_model.zip

    Or use the GUI: 1. Right-click on the models folder (or checkpoints in older projects) 2. Select "📥 Import Model..." 3. Choose a model package file

    Exporting Models:

    Share or backup your trained models:

    crackz model export --project ./my_project --out my_model.zip

    Or use the GUI: 1. Right-click on the models folder (or checkpoints in older projects) 2. Select "📦 Export Model..." 3. Choose where to save the package

    Model packages are portable zip files containing the checkpoint and metadata, making it easy to transfer models between projects, team members, or deployment environments.

    Switching Encoders Mid-Project

    To change encoder on an existing project: 1. Edit project.yaml → ai.model.encoder 2. Re-train the model: crackz detect train --project <name> 3. New checkpoint will use updated encoder

    See Configuration Reference for complete model configuration options.

    6. Typical Workflows¶

    6.1 Create a New Project¶

    CLI: 

    crackz init --name harbor-inspection-2025 --description "Q1 2025 harbor crack survey"

    GUI: 1. Launch: crackz-gui 2. File → New Project (Cmd/Ctrl+N) 3. Select base folder and enter project name 4. Project structure created automatically

    Advanced Options: 

    # Create with custom settings
crackz init --name custom-project --force  # Overwrite if exists

# Initialize from template (future)
crackz init --name new-project --template harbor-config.yaml

    6.2 Import Images¶

    From Local Directory: 

    crackz import-images \
  --project harbor-inspection-2025 \
  --src ~/Pictures/harbor-photos \
  --type raw \
  --size 512 512

    With Ground Truth Masks: 

    crackz import-images \
  --project harbor-inspection-2025 \
  --src ~/labeled-data/images \
  --src-masks ~/labeled-data/masks \
  --type train \
  --size 512 512

    Batch Import Multiple Splits: 

    # Training data
crackz import-images --project my-project --src train_imgs --src-masks train_masks --type train --size 512 512

# Validation data
crackz import-images --project my-project --src val_imgs --src-masks val_masks --type val --size 512 512

# Test data
crackz import-images --project my-project --src test_imgs --src-masks test_masks --type test --size 512 512

    Supported Formats: - Images: .jpg, .jpeg, .png, .bmp, .tif, .tiff - Masks: .png (grayscale, 0=background, 255=crack)

    Image Preprocessing: - Resizing with aspect ratio preservation - Zero-padding to target size - Normalization (mean/std from ImageNet)

    6.3 Train a Model¶

    Basic Training: 

    crackz detect train --project my-project

    With Runtime Overrides: 

    crackz detect train \
  --project my-project \
  --epochs 20 \
  --batch-size 8 \
  --learning-rate 0.001

    Note: Runtime overrides are not saved to project.yaml - they're for experimentation only.

    GPU Training: 

    # Automatically uses GPU if available
crackz detect train --project my-project --epochs 50

# Verify GPU is being used (check logs)
tail -f my-project/logs/crackz.log | grep -i cuda

    Monitor Training Progress: 

    # Watch loss in real-time
tail -f my-project/artifacts/metrics.json

# Or use TensorBoard (if enabled)
tensorboard --logdir my-project/artifacts/tensorboard

    Early Stopping: Training automatically stops if validation loss doesn't improve for 5 epochs (configurable in project.yaml).

    6.4 Run Detection¶

    CPU Detection: 

    crackz detect run --project my-project

    GPU Detection: 

    # Uses GPU automatically if available
crackz detect run --project my-project

# Force CPU (even with GPU available)
CUDA_VISIBLE_DEVICES="" crackz detect run --project my-project

    Model Selection:

    By default, detection automatically selects the best available checkpoint. You can override this with the --model option:

    # Auto-select (default): best.ckpt > last.ckpt > final.ckpt
crackz detect run --project my-project

# Explicitly use best checkpoint
crackz detect run --project my-project --model best

# Use most recent checkpoint (useful during iterative development)
crackz detect run --project my-project --model last

# Use final checkpoint
crackz detect run --project my-project --model final

# Use specific epoch checkpoint (e.g., epoch-0.9234.ckpt)
crackz detect run --project my-project --model epoch-0.9234

    Checkpoint Priority (Auto-selection): 1. best.ckpt - Highest validation IoU during training (recommended for production) 2. last.ckpt - Most recent training checkpoint 3. final.ckpt - Final training checkpoint

    When to Use Each: - Auto-select (no --model flag): Standard production inference - --model best: Explicitly ensure highest-performing model is used - --model last: Test most recent training state during development - --model final: Use final training state (may differ from best if validation IoU decreased) - --model epoch-X: Compare performance across different epochs or reproduce specific results

    Example: Compare Models: 

    # Run detection with different checkpoints to compare results
crackz detect run --project my-project --model best
mv my-project/detections my-project/detections-best

crackz detect run --project my-project --model last
mv my-project/detections my-project/detections-last

crackz detect run --project my-project --model epoch-0.8532
mv my-project/detections my-project/detections-epoch-0.8532

# Compare detection outputs side by side

    Detection on Specific Split: 

    # Detect on raw images (default)
crackz detect run --project my-project

# Detect on test set (with metrics if masks available)
crackz detect run --project my-project --split test

    Batch Processing: 

    # Process multiple projects
for project in project1 project2 project3; do
    crackz detect run --project $project
done

    Docker Detection: 

    # CPU
docker run --rm \
  -v $(pwd)/my-project:/home/app/my-project \
  ghcr.io/anaxiatech-ab/crackz-cli:latest \
  detect run --project /home/app/my-project

# GPU
docker run --gpus all --rm \
  -v $(pwd)/my-project:/home/app/my-project \
  ghcr.io/anaxiatech-ab/crackz-cli:gpu \
  detect run --project /home/app/my-project

    6.5 View Metrics (TensorBoard)¶

    Enable TensorBoard in Configuration:

    Edit project.yaml: 

    training:
  tensorboard: true

    Or create a config override: 

    # tensorboard-config.yaml
training:
  tensorboard: true

    Start TensorBoard: 

    # After training with tensorboard enabled
tensorboard --logdir my-project/artifacts/tensorboard

# Open browser to http://localhost:6006

    What You'll See: - Loss curves (training & validation) - IoU metrics over epochs - Learning rate schedule - Sample predictions (if configured)

    Alternative: View JSON Metrics 

    # Quick summary
cat my-project/artifacts/metrics.json | python -m json.tool

# Extract specific metrics
cat my-project/artifacts/metrics.json | jq '.final_val_iou'

    See Configuration Reference - TensorBoard Integration for details.

    6.6 Clean and Maintain Projects¶

    Preview Cleanup: 

    crackz clean --project my-project --dry-run

    Clean Logs and Artifacts: 

    crackz clean --project my-project

    Clean Logs Only: 

    crackz clean --project my-project --logs-only

    What Gets Removed: - *.log files - Temporary training artifacts - Old checkpoint files (keeps best/last) - Detection outputs (optional)

    Checkpoint Pruning:

    Keep only the best N checkpoints (configured in project.yaml): 

    training:
  checkpoint:
    save_top_k: 3  # Keep top 3 checkpoints by validation loss

    Manual pruning: 

    # Remove all but the last checkpoint
rm my-project/checkpoints/*.ckpt
# (except last-*.ckpt)

# Or keep only best checkpoint
rm my-project/checkpoints/epoch*.ckpt
# (keep best-*.ckpt)

    6.7 Package or Distribute¶

    Export Unified Configuration: 

    crackz export-config \
  --project my-project \
  --out my-project-snapshot.yaml

    Share Project: 

    # Create archive (excluding large files)
tar -czf my-project.tar.gz \
  --exclude='checkpoints' \
  --exclude='detections' \
  my-project/

# Send to collaborator
# They extract and run:
tar -xzf my-project.tar.gz
crackz detect run --project my-project  # Downloads default checkpoint if missing

    Docker Image Distribution:

    See Distribution Guide for: - Building custom Docker images - PyInstaller standalone executables - Wheel distribution to customers - Azure deployment patterns

    # Build documentation

    7.4 PowerShell Helpers (Windows)¶

    Create PowerShell Alias: 

    # Add to $PROFILE
function Invoke-Crackz {
    docker run --rm -v ${pwd}:/home/app ghcr.io/anaxiatech-ab/crackz-cli:latest @args
}
Set-Alias crackz Invoke-Crackz

# Usage
crackz detect run --project /home/app/my-project

    Batch Processing Script: 

    # process-all.ps1
$projects = Get-ChildItem -Directory -Filter "*-project"
foreach ($project in $projects) {
    Write-Host "Processing $($project.Name)..."
    crackz detect run --project $project.FullName
}

    See Docker Guide for comprehensive Docker usage.

    8. GUI Quick Tour¶

    8.1 Launching the GUI¶

    crackz-gui

    Or: 

    python -m crackz.gui.crackz_gui

    8.2 Main Interface¶

    Window Layout: - Left Sidebar: Project tree browser (images, masks, artifacts) - Center Pane: Preview area (thumbnails, text files, JSON) - Top Menu: File, Edit, View, Help

    Key Features: - Project Browser: Navigate project structure with folder tree - Image Preview: Thumbnail grid for image directories - Text Preview: Syntax-highlighted JSON/YAML/Markdown viewer - Double-click Images: Opens full-size popup - Context Menu: Right-click for quick actions (import, clean, open in explorer)

    8.3 Main Actions¶

    Create New Project: 1. File → New Project (Cmd/Ctrl+N) 2. Select base directory 3. Enter project name (subfolder auto-created) 4. Click "Create"

    Open Existing Project: 1. File → Open Project (Cmd/Ctrl+O) 2. Navigate to project folder 3. Select project.yaml

    Import Images: 1. Right-click on images/raw (or other split) 2. Select "Import Images" 3. Choose source directory 4. Configure resize options 5. Click "Import"

    10. Troubleshooting¶

    10.1 Installation Issues¶

    Problem: Installation fails with dependency errors

    Solution: 

    # Update pip and setuptools
pip install --upgrade pip setuptools

# Download and install from GitHub Release
wget https://github.com/Anaxiatech-AB/crackz/releases/download/vVERSION/crackz-VERSION-py3-none-any.whl
pip install crackz-VERSION-py3-none-any.whl

    Problem: CUDA not detected despite having GPU

    Solution: 

    # Verify CUDA installation
nvidia-smi

# Check PyTorch CUDA support
python -c "import torch; print(torch.cuda.is_available())"

# Reinstall PyTorch with CUDA
pip uninstall torch torchvision
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121

    10.2 Import/Training Issues¶

    Problem: No images found in training split

    Solution: - Verify images are in images/train/ (not images/raw/) - Check file extensions (.jpg, .jpeg, .png, .bmp, .tif, .tiff only) - Ensure import command used --type train

    Problem: Training says "No masks found"

    Solution: - Masks required for train/val/test splits - Check masks are in masks/train/ with same filenames as images - Masks must be grayscale PNG: 0=background, 255=crack

    Problem: Out of memory during training

    Solution: 

    # Reduce batch size
crackz detect train --project my-project --batch-size 1

# Or reduce image size
crackz import-images --project my-project --src ./data --type train --size 256 256

# Monitor GPU memory
nvidia-smi -l 1  # Update every second

    10.3 Detection Issues¶

    Problem: Empty detections directory after running detect

    Solution: - Check logs: tail my-project/logs/crackz.log - Verify images exist in target split (default: raw/) - Ensure checkpoint exists: ls my-project/models/ (or my-project/checkpoints/ in older projects) - Try: crackz detect run --project my-project --debug

    Problem: Detection results look wrong (too many/few cracks)

    Solution: - Adjust threshold in project.yaml: 

    detection:
  threshold: 0.5  # Increase to reduce false positives (0.7)
                   # Decrease to catch more cracks (0.3)
    - Retrain model with more/better labeled data - Check that images are similar to training data

    10.4 Logging Issues¶

    Problem: No logs written

    Solution: 

    # Check permissions
ls -la $(python -c "import tempfile; print(tempfile.gettempdir())")/crackz_logs

# Set explicit log directory
export CRACKZ_LOG_DIR=~/crackz-logs
mkdir -p ~/crackz-logs
crackz detect run --project my-project

    Problem: Central logs filling up disk

    Solution: 

    # Clean old logs
rm -rf $CRACKZ_LOG_DIR/*.log

# Or set retention policy (future feature)
# See configuration.md for log rotation settings

    11.2 Configuration¶

    Q: Where do logs go?

    A: Crackz uses a hybrid logging system: - Central logs: $CRACKZ_LOG_DIR (env var) or system temp (e.g., /tmp/crackz_logs) - Project logs: <project>/logs/ (always, in addition to central)

    Both log sinks are active when a project is loaded.

    Q: How do I override epochs without changing project.yaml?

    A: Use runtime overrides (CLI flags): 

    crackz detect train --project my-project --epochs 50 --batch-size 8

    These are not saved to project.yaml - for permanent changes, edit the YAML directly or use the GUI settings dialog.

    Q: Can I use a custom YAML config file?

    A: Yes: 

    crackz detect run --cfg my-custom-config.yaml

    Or export a snapshot: 

    crackz export-config --project my-project --out snapshot.yaml
crackz detect run --cfg snapshot.yaml

    11.3 Data & Models¶

    Q: What image formats are supported?

    A: .jpg, .jpeg, .png, .bmp, .tif, .tiff

    Q: What should mask images look like?

    A: Grayscale PNG files where: - 0 (black) = background - 255 (white) = crack

    Masks must have the exact same filename as corresponding images.

    Q: Can I use pre-trained models from other sources?

    A: Crackz uses segmentation models from segmentation-models-pytorch. You can: - Use built-in encoders (ResNet, EfficientNet, etc.) - Load custom checkpoints with --checkpoint <path> - Transfer learning from ImageNet pretrained weights (default)

    Q: How do I improve detection accuracy?

    A: 1. Add more training data (especially hard examples) 2. Balance your dataset (similar number of cracked/non-cracked images) 3. Increase training epochs (default is often too low) 4. Adjust threshold (detection sensitivity) 5. Try different encoders (edit project.yaml → model.encoder)

    11.4 Performance¶

    Q: How can I speed up training?

    A: - Use GPU (10-50x faster) - Increase --batch-size (up to GPU memory limit) - Reduce image resolution (--size 256 256 instead of 512 512) - Use a smaller encoder (e.g., mobilenet_v2 vs resnet50)

    Q: Can I run multiple detections in parallel?

    A: Yes, either: - Multiple Docker containers on same host - Azure Batch for distributed processing - Bash loop with & for background jobs: 

    for p in project1 project2 project3; do
    crackz detect run --project $p &
done
wait

    12. Glossary¶

    Artifact: Generated output file from training or detection (metrics, plots, annotated images).

    Central Log: System-wide log location (before/outside specific projects), controlled by CRACKZ_LOG_DIR.

    Checkpoint: Saved model weights (.ckpt file) from a training run. Used for resuming training or running detection.

    Detection: Inference process that applies a trained model to identify cracks in images.

    Encoder: Backbone network of the segmentation model (e.g., ResNet, EfficientNet). Extracts features from images.

    IoU (Intersection over Union): Metric measuring overlap between predicted and ground truth masks. Range: 0-1 (higher is better).

    Mask: Binary image representing ground truth (training) or predicted (detection) crack locations.

    Project: Self-contained directory with images, configuration, and outputs following Crackz structure.

    Schema Version: Version number in project.yaml indicating config format. Used for migrations when format changes.

    Split: Data subset category - one of raw, train, val, or test.

    Threshold: Confidence level (0-1) for classifying pixels as crack vs. background. Lower = more sensitive.
