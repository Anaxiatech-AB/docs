    Quickstart¶

    This guide walks you through creating a project, importing images, and running detection (CPU or Docker) in a few minutes.

    First time user? Check out the Easy Install Guide for simplified installation instructions.

    Looking to tune performance or add reproducibility? Jump to Configuration – Checkpoint Management or the Advanced Performance page.

    Prerequisites¶

    • Python 3.11+ (if running locally)
    • (Optional) CUDA‑capable GPU + drivers (if you plan GPU training/detection)
    • (Optional) Docker (for containerized workflow)

    1. Install (local developer setup with uv)¶

    uv sync --dev
uv run crackz --help
    Or with pip (runtime only, download from GitHub Releases): 
    # Install from GitHub Release (replace VERSION with actual version)
pip install https://github.com/Anaxiatech-AB/crackz/releases/download/vVERSION/crackz-VERSION-py3-none-any.whl

# Or download first, then install
wget https://github.com/Anaxiatech-AB/crackz/releases/download/v0.30.2/crackz-0.30.2-py3-none-any.whl
pip install crackz-0.30.2-py3-none-any.whl

    Note: Crackz is not available on PyPI. Install from GitHub Releases, a private package index, or use Docker images.

    2. Initialize a project¶

    Creates a directory with metadata + default folder structure. 

    crackz init --name demo-project
    This produces (simplified): 
    demo-project/
  images/
    raw/  (place original images here – optional prior to import)
    train/ val/ test/ (populated by import step)
  masks/
  artifacts/
  project.yaml

    Using the GUI: You can also create and manage projects via the graphical interface: 

    crackz-gui
    Use File → New Project (Cmd/Ctrl+N) or the welcome screen to create a new project. The GUI will help you select a base folder and automatically create the project structure.

    3. Import images¶

    Resize & normalize raw images into a split (train/val/test/raw). Example (raw images in ./samples): 

    crackz import-images \
  --project demo-project \
  --src ./samples \
  --type raw \
  --size 512 512 \
  --quality 90
    If you also have masks in ./samples/masks use the same command (they are picked up automatically) or specify --masks_src.

    Repeat for other splits as needed: 

    crackz import-images --project demo-project --src ./samples --type train --size 512 512
crackz import-images --project demo-project --src ./samples --type val   --size 512 512

    Automatic split (recommended for new projects): Instead of manually running import multiple times, use --split to automatically distribute images: 

    crackz import-images \
  --project demo-project \
  --src ./samples \
  --split \
  --train-ratio 0.7 \
  --val-ratio 0.15 \
  --test-ratio 0.15 \
  --size 512 512
    This shuffles images randomly and distributes them across train/val/test directories. Masks are automatically matched and distributed with their images. For reproducible splits, add --random-seed 42.

    Use --overwrite to regenerate processed images.

    4. Run detection¶

    crackz detect run --project demo-project
    You can also supply a configuration file instead of --project: 
    crackz detect run --cfg path/to/config.yaml

    Runtime estimation: When you run detection, Crackz will now display: - Estimated time before starting (based on number of images and batch size) - Elapsed time during processing - Estimated time remaining

    The progress bar will show time information like: 

    Detection: Processed image 50/100 | elapsed: 1m 30s | remaining: 1m 25s

    5. Train (optional)¶

    If you prepared the dataset for training: 

    crackz detect train --project demo-project
    (Progress appears with a tqdm bar.)

    Note: Training vs. Pre-Trained Models

    Crackz supports two workflows:

    Option A: Train Your Own Model - Use when you have domain-specific data or unique defect types - Requires labeled training data (images + masks for train/val/test splits) - Creates custom checkpoint tuned to your specific use case - Example: Harbor-specific crack patterns, custom surface deviations

    Option B: Use Pre-Trained Models - Use for quick deployment or standard crack detection scenarios - Acquire ready-made checkpoint from model providers, partners, or previous training runs - Place checkpoint in demo-project/artifacts/training/checkpoints/best.ckpt - Skip training and go directly to crackz detect run - Example: Standard concrete crack detection, proof-of-concept deployments

    If using a pre-trained model, you can skip this training step and proceed directly to detection (step 6).

    Runtime estimation: Training also displays estimated runtime before starting: - Total estimated time based on epochs, dataset size, and batch size - Elapsed time for each epoch - Estimated time remaining for the entire training run

    Example progress output: 

    Training: epoch 3/10 started | elapsed: 5m 12s | remaining: 12m 5s

    Enable TensorBoard Logging¶

    To visualize training metrics in real-time, enable TensorBoard in your project configuration:

    1. Edit demo-project/demo-project_project.yaml: 

      ai:
  training:
    tensorboard: true

    2. Run training: 

      crackz detect train --project demo-project

    3. In a separate terminal, launch TensorBoard: 

      tensorboard --logdir demo-project/artifacts/training/tensorboard

    4. Open http://localhost:6006 in your browser to view metrics.

    Fast Training Overrides¶

    For a smoke test / CI pipeline you can drastically shorten the run: 

    crackz detect train --project demo-project --epochs 1 --batch-size 1
    These overrides: - Apply only to the current invocation - Do not modify the stored project YAML - Are ideal for verifying Docker images and end‑to‑end wiring

    6. Logging & verbosity¶

    Add --debug for detailed logs or --quiet for warnings only: 

    crackz --debug detect run --project demo-project
    Change log directory: 
    crackz --log-dir run_logs detect run --project demo-project

    7. Environment variables¶

    Variable Purpose Default
    CRACKZ_LOG_DIR Where logs are written logs
    PYTHONUNBUFFERED Immediate output flushing 1

    Override at runtime: 

    CRACKZ_LOG_DIR=logs_debug crackz detect run --project demo-project

    8. Using Docker (CPU image)¶

    Container images now start in the non‑root user home /home/app. Mount your host project directory at that path to persist the project.

    Build (if using local repo): 

    docker build -t crackz-cli .
    Initialize project (persisting on host under ./project): 
    mkdir -p project
docker run --rm -v %cd%\project:/home/app crackz-cli init --name demo-project
    Import images: 
    docker run --rm -v %cd%\project:/home/app -v %cd%\samples:/data \
  crackz-cli import-images --project /home/app/demo-project --src /data --type raw --size 512 512
    Run detection: 
    docker run --rm -v %cd%\project:/home/app crackz-cli detect run --project /home/app/demo-project

    9. Docker variants¶

    Tag Purpose
    latest Full multi-stage image
    slim Minimal runtime (wheel only)
    gpu CUDA runtime (requires --gpus all)

    10. GPU (container)¶

    docker build -f Dockerfile.gpu -t crackz-cli:gpu .
docker run --gpus all --rm -v %cd%\project:/home/app crackz-cli:gpu detect run --project /home/app/demo-project

    12. Troubleshooting¶

    Issue Suggestion
    Missing project/config error Provide --project or --cfg
    No logs written Check CRACKZ_LOG_DIR or permissions
    Slow first run Torch wheels + cache population
    CUDA not detected Verify driver + base image (for GPU variant)

    13. Upgrading Legacy Projects¶

    If you opened an older project (missing schema_version) after upgrading Crackz: 

    crackz migrate --project ./legacy_project
    CI auto-migration (non-interactive): 
    CRACKZ_AUTO_MIGRATE=1 crackz detect run --project legacy_project
    A .bak copy is written. Details: see Migration page.
