    Azure AI Integration Roadmap¶

    Hybrid cloud-edge architecture for enhanced Crackz capabilities

    Status: Planned | Target: Q2-Q3 2025

    Executive Summary¶

    This roadmap outlines optional Microsoft Azure AI (Foundry) integration for Crackz while preserving its core offline-first architecture. Azure services will enhance training speed, annotation efficiency, and AI chat capabilities without compromising on-premises deployment requirements.

    Key Principle: All Azure features are opt-in enhancements. Crackz continues to work fully offline with core features unchanged.

    Business Value¶

    For Small Customers (1-5 users)¶

    • ✅ No upfront GPU hardware investment ($5,000-$15,000 saved)
    • ✅ Pay-as-you-go training ($5-20/month vs fixed costs)
    • ✅ Faster time-to-production (train models in minutes vs hours)

    For Enterprise Customers (50+ users)¶

    • ✅ Azure AD integration (Single Sign-On)
    • ✅ Compliance certifications (SOC 2, ISO 27001, GDPR)
    • ✅ Private endpoints (no public internet exposure)
    • ✅ Scalable training (100+ projects simultaneously)

    For Air-Gapped Environments (Maritime/Defense)¶

    • ✅ Train models in secure Azure Government Cloud
    • ✅ Download checkpoints to air-gapped network
    • ✅ Zero cloud dependency after deployment

    Core Principles¶

    1. Offline-First: All core features work without Azure
    2. Opt-In Cloud: Azure services are optional enhancements
    3. Checkpoint Portability: Models trained in Azure work offline
    4. Data Privacy: Customer controls what data goes to cloud
    5. Cost Transparency: Estimate costs before using cloud services

    Use Cases & Azure Services¶

    1. Cloud-Based Model Training (Highest Priority)¶

    Problem: Training segmentation models on-premises is slow without GPUs.

    Azure Solution: Azure Machine Learning + GPU clusters (H100, A100, V100)

    Value: - 10x faster training (minutes vs hours) - No local GPU hardware required - Automatic hyperparameter tuning (Azure AutoML) - Experiment tracking with MLflow

    Workflow: 

    1. Engineer uploads training images via Crackz CLI/GUI
2. Crackz uploads dataset to Azure Blob Storage (encrypted)
3. Azure ML trains model on H100 GPUs
4. Crackz downloads trained checkpoint
5. Offline detection works normally with downloaded checkpoint

    Cost Estimate: $2-10 per training run (depending on data size, GPU type)

    CLI Command (proposed): 

    crackz cloud train \
  --project harbor-2025 \
  --azure \
  --compute gpu-cluster-h100 \
  --epochs 50 \
  --estimate-cost  # Show cost before proceeding

    GUI Integration: "Train in Cloud" button with cost preview dialog

    2. AI-Assisted Mask Annotation¶

    Problem: Manual mask annotation is tedious (30-60 seconds per image).

    Azure Solution: Azure Computer Vision Custom Vision + SAM (Segment Anything Model)

    Value: - 80% reduction in annotation time - Higher quality labels (Azure CV pre-trained on millions of images) - Ensemble predictions (Azure + local model)

    Workflow: 

    1. Engineer selects 100 unlabeled images
2. Crackz sends images to Azure Computer Vision
3. Azure returns suggested masks (80-90% accurate)
4. Engineer reviews/corrects in GUI (10-20% effort vs full manual)
5. Saves corrected masks locally
6. Works offline after initial suggestion

    Cost Estimate: ~$0.001 per image (1000 images = $1)

    CLI Command (proposed): 

    crackz masks suggest \
  --project harbor-2025 \
  --azure \
  --prompt "cracks in concrete" \
  --batch 100

    3. Enhanced AI Chat with Azure OpenAI¶

    Problem: Current AI Chat uses Anthropic Claude API. Enterprise customers need Azure-native options.

    Azure Solution: Azure OpenAI Service (GPT-4 Turbo, GPT-4o)

    Value: - Enterprise security (Azure AD, private endpoints) - Data residency compliance (EU/US regions) - Lower cost for high volume ($0.03 vs $0.015 per 1K tokens) - Hybrid: Use Azure OpenAI online, cache responses offline

    Workflow: 

    1. Engineer asks: "Why is my model's IoU only 0.72?"
2. AI Chat analyzes project context (training logs, config)
3. AI Chat suggests: "Your validation split is too small (only 50 images). Recommendation: increase to 150+ images for stable metrics."
4. Response cached locally for offline replay

    Cost Estimate: ~$0.03 per 1000 tokens (cheaper than Claude for bulk usage)

    Configuration (proposed): 

    # project.yaml
ai_chat:
  provider: azure-openai  # or anthropic
  model: gpt-4-turbo
  azure:
    endpoint: https://your-region.openai.azure.com/
    deployment: gpt-4-turbo

    4. Automated Compliance Reporting¶

    Problem: Current Word report generator is template-based. Customers need industry-standard compliance formats.

    Azure Solution: Azure Document Intelligence (formerly Form Recognizer)

    Value: - Industry-standard compliance formats (ISO-9001, ASTM-D4788) - Automated quality control checks - Digital signatures for audit trails - PDF/A archival format

    Workflow: 

    1. Engineer completes detection on harbor project
2. Clicks "Generate Compliance Report" (ISO-9001 template)
3. Azure Document Intelligence applies template
4. PDF generated with digital signature
5. Exported to project/reports/harbor-2025-compliance.pdf

    Cost Estimate: ~$0.01 per document processed

    Implementation Roadmap¶

    Phase 1: Foundation (4 weeks) - Q2 2025¶

    Goal: Establish Azure connectivity and authentication

    Tasks: - [ ] Create src/crackz/cloud/ module - [ ] Add Azure SDK dependencies (azure-ai-ml, azure-identity, azure-storage-blob) - [ ] Implement authentication (Azure AD + service principal) - [ ] Add AzureConfig to src/crackz/config/ - [ ] Create cost estimation utility - [ ] Write ADR-019: Optional Azure AI Integration

    Deliverables: - Working Azure authentication - Configuration schema for Azure services - Cost estimator for all services

    Success Criteria: - crackz cloud auth login command works - Cost estimation within 10% of actual Azure billing

    Phase 2: Cloud Training (6 weeks) - Q2 2025¶

    Goal: Train models in Azure ML, download checkpoints for offline use

    Tasks: - [ ] Implement AzureTrainingService - [ ] Dataset upload to Azure Blob Storage (with encryption) - [ ] Submit PyTorch Lightning training jobs to Azure ML - [ ] Automatic checkpoint download on completion - [ ] CLI command: crackz cloud train --azure --compute gpu-cluster - [ ] GUI panel: "Train in Cloud" button with cost preview - [ ] Training metrics sync (TensorBoard logs from Azure)

    Deliverables: - Functional cloud training workflow - GUI integration with progress tracking - Documentation: "Cloud Training Guide"

    Success Criteria: - Train 1000-image dataset in <10 minutes on Azure H100 - Downloaded checkpoint works offline with 0% accuracy degradation - Cost <$5 per training run for standard datasets

    Phase 3: AI-Assisted Annotation (4 weeks) - Q3 2025¶

    Goal: Reduce manual annotation time by 80%

    Tasks: - [ ] Enhance MaskSuggester with Azure Computer Vision - [ ] Batch processing (100+ images) - [ ] Ensemble predictions (Azure + local model if available) - [ ] Cost estimation before API calls - [ ] Offline fallback to existing local suggester - [ ] CLI command: crackz masks suggest --azure --batch 100 - [ ] GUI: "Suggest Masks from Cloud" button

    Deliverables: - Azure CV integration in mask suggestion workflow - Batch processing with progress tracking - Documentation: "AI-Assisted Annotation Guide"

    Success Criteria: - 80% reduction in annotation time (measured in user study) - Suggested masks achieve >85% IoU before manual correction - Cost <$1 per 1000 images

    Phase 4: Enhanced AI Chat (3 weeks) - Q3 2025¶

    Goal: Enterprise-grade AI Chat with Azure OpenAI

    Tasks: - [ ] Add Azure OpenAI as optional backend - [ ] Configuration toggle (Anthropic vs Azure) - [ ] Project context injection (training logs, detection results) - [ ] Response caching for offline replay - [ ] Token usage tracking and cost monitoring - [ ] Private endpoint support (Azure VNet)

    Deliverables: - Dual-provider AI Chat (Anthropic + Azure OpenAI) - Offline response cache - Documentation: "AI Chat Configuration Guide"

    Success Criteria: - Feature parity with existing Anthropic integration - <2 second response time for cached queries - Cost <50% of Anthropic for high-volume users

    Phase 5: Advanced Reporting (4 weeks) - Q3 2025¶

    Goal: Industry-standard compliance reporting

    Tasks: - [ ] Azure Document Intelligence integration - [ ] Compliance template library (ISO-9001, ASTM-D4788, EN-1504) - [ ] Digital signature support (Azure Key Vault) - [ ] PDF/A archival format - [ ] Automated quality control checks - [ ] CLI command: crackz report generate --template ISO-9001 --azure

    Deliverables: - 3+ compliance templates - Digital signature workflow - Documentation: "Compliance Reporting Guide"

    Success Criteria: - Reports pass ISO-9001 validation - Digital signatures verified by Adobe Acrobat - Cost <$0.05 per report

    project.yaml Extension¶

    # New section added to project.yaml
azure:
  enabled: false  # Default: offline-only

  # General settings
  subscription_id: "your-subscription-id"
  resource_group: "crackz-rg"
  region: "eastus"  # or "westeurope", "uksouth", etc.

  # Authentication
  auth:
    method: azure-cli  # or service-principal, managed-identity
    tenant_id: "..."  # Only for service-principal
    client_id: "..."
    # client_secret stored in Azure Key Vault

  # Training
  training:
    enabled: false
    workspace: "crackz-ml-workspace"
    compute_target: "gpu-cluster-h100"  # or gpu-cluster-a100, gpu-cluster-v100
    environment: "crackz-pytorch-env:1"
    max_cost_per_run: 10.0  # USD, abort if exceeded

  # Computer Vision
  computer_vision:
    enabled: false
    endpoint: "https://eastus.api.cognitive.microsoft.com/"
    api_version: "2023-10-01"
    # API key stored in Azure Key Vault

  # OpenAI
  openai:
    enabled: false
    endpoint: "https://your-openai.openai.azure.com/"
    deployment: "gpt-4-turbo"  # or gpt-4o, gpt-35-turbo
    api_version: "2024-02-01"
    max_tokens: 1000
    temperature: 0.7

  # Storage
  storage:
    account_name: "crackzdatastorage"
    container_training: "training-datasets"
    container_models: "trained-models"
    encryption: "microsoft-managed"  # or customer-managed

  # Document Intelligence
  document_intelligence:
    enabled: false
    endpoint: "https://eastus.api.cognitive.microsoft.com/"
    api_version: "2023-07-31"

  # Cost controls
  cost_controls:
    monthly_budget: 100.0  # USD
    alert_threshold: 0.8  # Alert at 80% of budget
    auto_disable_at_budget: true  # Disable Azure features when budget exceeded

    Security & Compliance¶

    Data Privacy¶

    Customer Data Control: - Customers choose what data goes to Azure (opt-in per project) - Data encrypted in transit (TLS 1.2+) and at rest (AES-256) - Data residency options (EU, US, UK, etc.) - Data retention policy configurable (7-90 days, or permanent)

    Sensitive Data Handling: - PII detection before upload (block if detected) - Azure Private Link for network isolation - Customer-managed encryption keys (optional)

    Compliance Certifications¶

    Azure AI services are certified for: - ✅ SOC 2 Type II (security, availability, confidentiality) - ✅ ISO 27001 (information security) - ✅ GDPR (EU data protection) - ✅ HIPAA (healthcare data - if needed) - ✅ FedRAMP (US government - Azure Government Cloud)

    Access Control¶

    Authentication: - Azure AD integration (SSO) - Multi-factor authentication (MFA) - Conditional access policies - Service principals for automation

    Authorization: - Role-based access control (RBAC) - Least privilege principle - Audit logs for all operations

    Migration Path for Existing Customers¶

    Scenario 1: On-Premises Only → Hybrid (Training in Cloud)¶

    Before: - Local GPU server ($10,000 hardware) - 4-hour training time per model - Limited to 1 training job at a time

    After: - No GPU hardware needed - 30-minute training time per model (H100) - Unlimited parallel training jobs - $5/training run = $100/month (20 runs) - ROI: Hardware cost recovered in 100 months, but faster iteration pays off sooner

    Migration Steps: 1. Enable azure.training.enabled: true in project.yaml 2. Authenticate: crackz cloud auth login 3. First cloud training: crackz cloud train --project demo --azure --compute gpu-cluster-h100 4. Download checkpoint automatically 5. Continue offline detection as normal

    Scenario 2: Anthropic AI Chat → Azure OpenAI¶

    Before: - Anthropic Claude API ($0.015/1K tokens) - 100,000 tokens/month = $1.50/month

    After: - Azure OpenAI GPT-4o ($0.005/1K input tokens) - 100,000 tokens/month = $0.50/month - Savings: 67% cost reduction - Bonus: Enterprise compliance (Azure AD, private endpoints)

    Migration Steps: 1. Set ai_chat.provider: azure-openai in project.yaml 2. Configure Azure OpenAI endpoint 3. Existing chat history preserved 4. Seamless fallback to Anthropic if Azure unavailable

    Risks & Mitigations¶

    Risk 1: Vendor Lock-In¶

    Risk: Dependency on Azure-specific APIs.

    Mitigation: - ✅ All Azure features are optional - ✅ Core Crackz functionality unchanged - ✅ Checkpoints from Azure work offline (standard PyTorch format) - ✅ Abstract cloud interface (CloudTrainingService) supports multiple providers

    Risk 2: Cost Overruns¶

    Risk: Unexpected Azure charges.

    Mitigation: - ✅ Cost estimator before every operation - ✅ Monthly budget limits with auto-disable - ✅ Real-time cost tracking in GUI - ✅ Alert at 80% of budget

    Risk 3: Data Privacy Concerns¶

    Risk: Customer data sent to cloud without consent.

    Mitigation: - ✅ Opt-in per project (default: disabled) - ✅ PII detection before upload - ✅ Data encryption in transit and at rest - ✅ Customer-controlled data retention

    Risk 4: Network Dependency¶

    Risk: Cloud features break offline workflows.

    Mitigation: - ✅ Offline-first design unchanged - ✅ Graceful degradation (Azure unavailable → local fallback) - ✅ Checkpoints cached locally - ✅ AI Chat responses cached for offline replay

    Alternative Considered¶

    AWS Bedrock¶

    Pros: - Similar features (SageMaker, Rekognition, Bedrock LLMs) - Larger market share

    Cons: - More complex pricing - Less integrated AI tooling - Weaker enterprise compliance (vs Azure Government Cloud)

    Decision: Focus on Azure first, AWS support in 2026 if demand exists.

    Google Vertex AI¶

    Pros: - Strong TPU support - AutoML capabilities

    Cons: - Smaller enterprise footprint - Less Azure AD integration

    Decision: Not pursued at this time.
