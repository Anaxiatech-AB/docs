    Crackz¶

    AI-driven crack detection & analysis for harbor and bridge infrastructure.

    Enterprise AI-Powered Infrastructure Inspection¶

    Crackz is a commercial-grade crack detection and analysis solution designed for harbor facilities, bridges, and critical infrastructure. Reduce inspection costs by up to 70% while improving safety and consistency through automated AI-powered analysis.

    Transform your infrastructure management: Crackz provides a complete end‑to‑end workflow from image import through detection to comprehensive reporting—deployable on-premises, in containers, or air-gapped environments.

    New to Crackz? See our Customer Guide for use cases, ROI analysis, and getting started.

    Ready to install? Check out the Easy Install Guide for the simplest installation methods.

    Why Choose Crackz?¶

    For Infrastructure Managers & Asset Owners¶

    • Reduce costs – Process thousands of images in hours instead of weeks of manual inspection
    • Improve safety – Minimize physical inspections in hazardous locations
    • Early detection – Identify structural issues before they become critical and costly
    • Audit compliance – Complete documentation trail for regulatory requirements
    • Proven ROI – Typical customers save $25,000-$75,000 annually per inspection program

    For Technical Teams¶

    • Reproducible projects – Self‑contained folder structure (images, masks, artifacts, logs, metrics)
    • Fast experimentation – One‑line training overrides (--epochs, --batch-size) for rapid iteration
    • Hybrid logging – Central log sink + per‑project logs for troubleshooting and provenance
    • Scriptable & visual – Powerful CLI plus modern CustomTkinter GUI (dark mode by default)
    • Container friendly – Full / slim / GPU multi‑stage Docker images (optimized uv sync builds)
    • Extensible design – Pydantic configs, modular AI pipeline (PyTorch Lightning), plugin-ready architecture

    Model Flexibility & Use Cases¶

    Open Architecture for Multiple Applications

    Crackz supports different model types and workflows to match your specific needs:

    Model Types¶

    Default: Segmentation (Pixel-Level Analysis) - Binary segmentation: crack/no-crack, deviation/no-deviation - Multi-class segmentation: cracks, corrosion, spalling (configurable) - U-Net architecture with 20+ encoder options (ResNet, EfficientNet, MobileNet, etc.) - Outputs: Precise pixel masks showing defect locations

    Future: Classification (Whole-Image Analysis) - Rapid assessment: "Does this image contain cracks?" - Confidence scores for filtering and triage - Lighter-weight models for edge deployment

    Sample Use Cases¶

    Application Model Type Encoder Workflow
    Harbor wall crack detection Binary segmentation ResNet34 Train on labeled samples → Deploy
    Bridge multi-defect analysis Multi-class segmentation EfficientNet-B0 Use pre-trained model → Inspect
    Surface deviation mapping Binary segmentation MobileNetV2 Custom training → Edge deployment
    Quick image filtering Classification (future) MobileNetV2 Pre-trained → High-volume screening

    Two Paths to Production¶

    1. Train Your Own Model 

    # Import labeled data (images + masks)
crackz import-images --project my-harbor --src ./labeled/images --src-masks ./labeled/masks --type train --size 512 512
crackz import-images --project my-harbor --src ./labeled/val_imgs --src-masks ./labeled/val_masks --type val --size 512 512

# Train custom model
crackz detect train --project my-harbor --epochs 20

# Run detections
crackz detect run --project my-harbor
    When to use: Domain-specific imagery, unique defect types, custom requirements

    2. Use Pre-Trained Models 

    # Initialize project
crackz init --name harbor-inspection

# Acquire ready-made checkpoint (from model provider or partner)
# Place in: harbor-inspection/artifacts/training/checkpoints/best.ckpt

# Import images for inspection
crackz import-images --project harbor-inspection --src ./raw-photos --type raw --size 512 512

# Run detections with existing model
crackz detect run --project harbor-inspection
    When to use: Quick deployment, standard crack detection, proof-of-concept, consistent results across sites

    Encoder Selection Examples¶

    Configure in project.yaml or during training: 

    ai:
  model:
    encoder: resnet34           # Balanced accuracy/speed
    # encoder: efficientnet-b0  # Best accuracy, slower
    # encoder: mobilenet_v2     # Fast, edge-friendly
    encoder_weights: imagenet   # Transfer learning (recommended)
    num_classes: 1              # Binary (1) or multi-class (2+)

    See Configuration Reference and Architecture for complete details.

    Quick Start¶

    1. Install (CPU)¶

    Note: Crackz is not available on PyPI. Install from GitHub Releases, a private package index, or use Docker images.

    # Install from GitHub Release (replace VERSION with actual version)
pip install https://github.com/Anaxiatech-AB/crackz/releases/download/vVERSION/crackz-VERSION-py3-none-any.whl

# Example for v0.30.2:
pip install https://github.com/Anaxiatech-AB/crackz/releases/download/v0.30.2/crackz-0.30.2-py3-none-any.whl
    Or developer environment (with uv): 
    uv sync --dev
uv run crackz --help

    2. Initialize project¶

    crackz init --name demo

    3. Import images¶

    crackz import-images --project demo --src ./samples --type train --size 512 512
crackz import-images --project demo --src ./samples --type val   --size 512 512
    (Optional) raw images for later inference: 
    crackz import-images --project demo --src ./samples --type raw --size 512 512

    4. Train (full)¶

    crackz detect train --project demo
    Fast smoke (CI / local validation): 
    crackz detect train --project demo --epochs 1 --batch-size 1

    5. Run detection¶

    crackz detect run --project demo

    6. Inspect results¶

    • Training metrics: demo/artifacts/training/training_metrics.json
    • Detection images + metrics: demo/artifacts/detections/
    • Logs: demo/logs/crackz.log

    GUI Usage¶

    Launch: 

    crackz-gui
    Capabilities (current): - Splash + automatic dark theme - Recent projects list & quick open - Project structure browser - Run detection / training with progress bars (WIP expansion of result previews)

    Planned / extensible areas: - Inline metrics plots - Mask overlay / interactive threshold adjustment - Config editor & export inside GUI

    Smoke test (auto-close): 

    CRACKZ_GUI_SMOKE=1 crackz-gui

    See the GUI documentation for detailed information about GUI features, testing, and troubleshooting.

    Docker¶

    Tag Base Use Case
    latest python:<ver>-slim General local & CI usage
    slim python:<ver>-slim Minimal runtime (fast pull)
    gpu nvidia/cuda:runtime Training / detection with CUDA

    Build examples: 

    # Full
docker build -t crackz-cli .
# Slim
docker build -f Dockerfile.slim -t crackz-cli:slim .
# GPU (override Python / Torch index)
docker build -f Dockerfile.gpu -t crackz-cli:gpu \
  --build-arg PYTHON_VERSION=3.13 \
  --build-arg TORCH_INDEX_URL=https://download.pytorch.org/whl/cu118 .
    Run detection (CPU example): 
    docker run --rm -v "$(pwd)/demo:/home/app" crackz-cli detect run --project /home/app
    GPU: 
    docker run --gpus all --rm -v "$(pwd)/demo:/home/app" crackz-cli:gpu detect run --project /home/app

    Hybrid Logging¶

    • Central sink (pre‑project): CRACKZ_LOG_DIR env or --log-dir root option; fallback system temp.
    • Project sink: <project>/logs (stored as relative logs in YAML for portability).
    • Both active after project load; central lines aid troubleshooting init failures.

    Override example: 

    CRACKZ_LOG_DIR=central_logs crackz init --name demo
crackz --log-dir central_logs detect run --project demo

    Training Overrides (Runtime Only)¶

    Use for rapid iteration without altering saved config: 

    crackz detect train --project demo --epochs 2 --batch-size 4
    These modify in‑memory config only (not written back to YAML).
