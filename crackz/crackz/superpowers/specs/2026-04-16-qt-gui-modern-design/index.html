    Qt GUI Modern Design Spec¶

    Date: 2026-04-16
    Branch: feat/pyside6-migration
    Status: Approved for implementation

    Context¶

    The current Crackz GUI is built on CustomTkinter, which has four known pain points: poor native look and feel, missing widgets (no virtual list rendering, no GPU-composited image views), threading complexity, and fragile PyInstaller packaging. The feat/pyside6-migration branch is migrating to PySide6/Qt.

    This spec defines the visual design and UX structure for that migration — the palette, layout, component primitives, and interaction patterns that all panels should follow. It is not a full panel-by-panel implementation spec; that comes from the writing-plans output. The goal here is to establish the design language so that the Phase 0 shell + Explorer panel can be built to the right standard, and every subsequent panel has a clear template to follow.

    Design Decisions Summary¶

    Decision Choice Rationale
    Color palette Catppuccin Mocha Well-maintained OSS palette, dark + accessible, strong accent contrast
    Primary accent Mauve #cba6f7 Distinctive, not blue (avoids confusion with links/info)
    Layout Activity bar + side panel + main content Scales with feature growth; VS Code muscle memory
    Image viewer default Gallery strip + detail Triage is the primary workflow
    AI chat Slide-in right drawer Assistive tool, used alongside other panels, not instead
    Widget toolkit PySide6 QWidget (not QML) Per feasibility spec — solves all four pain points at lower cost
    Styling QSS stylesheet CSS-like, centralized, easily themed

    1. Design System¶

    1.1 Color Tokens¶

    All colors defined once in src/crackz/gui/style/theme.py as string constants, referenced throughout QSS. No hardcoded hex values in component files.

    # src/crackz/gui/style/theme.py

# Backgrounds (darkest → lightest)
BASE    = "#11111b"   # image viewer bg, deepest chrome
MANTLE  = "#1e1e2e"   # main content area
CRUST   = "#181825"   # activity bar, side panel, title bar, status bar

# Surfaces (interactive elements)
SURFACE0 = "#313244"  # cards, inputs, tree selection, toolbar buttons
SURFACE1 = "#45475a"  # borders, dividers, hover states
SURFACE2 = "#585b70"  # disabled state

# Text
TEXT      = "#cdd6f4"  # primary labels, file names
SUBTEXT1  = "#a6adc8"  # secondary info, metadata
OVERLAY0  = "#6c7086"  # hints, keyboard shortcuts, placeholder
OVERLAY1  = "#7f849c"  # very muted (timestamps, dimensions)

# Accents
MAUVE  = "#cba6f7"   # primary CTA, active activity bar item, section labels
BLUE   = "#89b4fa"   # links, info, compare mode accent
GREEN  = "#a6e3a1"   # success, clean/no-crack badge, status dot
RED    = "#f38ba8"   # high severity badge, error states
PEACH  = "#fab387"   # medium severity badge
YELLOW = "#f9e2af"   # warnings

# Semantic aliases (use these in components, not raw colors)
SEVERITY_HIGH   = RED
SEVERITY_MEDIUM = PEACH
SEVERITY_CLEAN  = GREEN
SEVERITY_NONE   = SURFACE0   # unprocessed

PRIMARY      = MAUVE
BORDER       = SURFACE1
BG_PANEL     = CRUST
BG_CONTENT   = MANTLE
BG_DEEP      = BASE

    1.2 Typography¶

    All text uses the system UI font (-apple-system, BlinkMacSystemFont, Segoe UI, sans-serif). No custom font downloads.

    Role Size Weight Color Notes
    Panel title 14px 600 TEXT Main heading per panel
    Section label 11px 600 MAUVE Uppercase, +1px letter-spacing
    Body 12px 400 TEXT File names, descriptions
    Secondary 10px 400 SUBTEXT1 Metadata, dimensions, timestamps
    Hint 10px 400 OVERLAY0 Keyboard shortcuts, placeholder text

    1.3 Spacing & Radius¶

    • Base unit: 4px
    • Component padding: 6–8px inner, 12px panel gutter
    • Border radius: 5–6px for cards and buttons; 4px for badges; 8px for large panels
    • Dividers: 1px solid SURFACE1

    1.4 QSS Approach¶

    One master stylesheet at src/crackz/gui/style/crackz.qss, loaded once at startup:

    # src/crackz/gui/app.py
from string import Template
with open(Path(__file__).parent / "style" / "crackz.qss") as f:
    app.setStyleSheet(Template(f.read()).substitute(**theme.__dict__))

    Color tokens are injected via string.Template so QSS uses $MAUVE, $CRUST, etc. (not {...} — that conflicts with QSS selector syntax). No runtime style overrides on individual widgets except for dynamic severity badge colors.

    Key measurements: - Activity bar: 44px wide, QWidget with vertical QVBoxLayout - Side panel: 220px default, resizable via QSplitter, min 160px - Status bar: 24px tall, custom QStatusBar subclass - AI chat drawer: 280px, slides in/out with QPropertyAnimation on width

    3. Activity Bar¶

    A narrow 44px-wide QWidget pinned to the left edge. Contains icon buttons that switch the active side panel.

    Sections (top to bottom)¶

    Icon Label Side panel content
    📁 Explorer Project file tree
    🔍 Detect Detection run controls + results list
    ⚡ Train Training config + live metrics
    🎯 Active Learning Entropy/uncertainty annotation queue
    — (spacer) —
    ⚙️ Settings App + project settings

    Active state: Left border 2px MAUVE + MAUVE/13% background tint on the icon tile.
    Hover state: SURFACE0 background, no border.
    Tooltip: Show label text on hover (Qt default tooltip, styled via QSS).

    Icons: Use QIcon loaded from SVG files in src/crackz/gui/assets/icons/. Single-color SVGs recolored via QSS color property (Qt 6.2+).

    4. Side Panel¶

    A QStackedWidget behind the activity bar. Each activity has its own panel widget pushed onto the stack. Switching activity bar icon calls stack.setCurrentIndex(n).

    4.1 Explorer Panel (Phase 0 reference implementation)¶

    The first panel to build — establishes the pattern for all others.

    Structure: 

    ┌──────────────────────────────┐
│ EXPLORER          [+] [📂]   │  ← Panel header: section label + toolbar actions
├──────────────────────────────┤
│ ▼ harbor-2024                │  ← QTreeView, custom CrackzTreeModel
│   ▶ images/         [3]●     │     Badge = unprocessed count
│   ▶ masks/                   │
│   ▶ results/                 │
│     project.yaml             │
├──────────────────────────────┤
│ ● harbor-2024                │  ← Project badge (bottom, always visible)
└──────────────────────────────┘

    Implementation notes: - QTreeView with QFileSystemModel subclass (CrackzFileModel) for file system representation - Context menu via customContextMenuRequested signal → QMenu - File selection emits signal → main content area updates - Project badge: custom QLabel widget at bottom of panel, shows active project name + green dot

    4.2 Remaining Panels (follow Explorer pattern)¶

    Each panel uses the same header structure (section label + optional toolbar actions) and CRUST background. Detailed design per panel is out of scope for this spec — panels are built once the shell + Explorer pattern is validated.

    Detect panel: Split into "Run" (controls: model selector, confidence threshold, run button) and "Results" (list of processed images with severity badges).

    Train panel: Two sub-sections — Config (epochs, batch size, model architecture) and Live Metrics (embedded matplotlib canvas via FigureCanvasQTAgg, loss + IoU curves updating in real time).

    Active Learning panel: Ranked list of unprocessed images ordered by uncertainty score, with annotation controls.

    Settings panel: Tab widget — App settings (theme light/dark toggle, API keys via keyring) and Project settings (split ratios, model config, log paths).

    5. Main Content Area¶

    5.1 Image Viewer (default view when a results folder is selected)¶

    Three modes, switched via toolbar toggle group. Gallery+Detail is the default.

    Toolbar (always visible): 

    [breadcrumb path]  |  [Gallery] [Single] [Compare]  |  [count summary]  [Export Report]

    Gallery + Detail mode (default)¶

    ┌──────────────────────────────────────────────────────────────┐
│ [thumb H] [thumb M] [thumb ✓] [thumb —] [thumb H] … +19     │  ← Thumbnail strip, 64×52px tiles
├───────────────────────────────────────────┬──────────────────┤
│                                           │ INSPECTOR        │
│   [large image, zoom/pan]                 │ File: img_001    │
│   crack overlay rendered on QGraphicsView │ Severity: ● High │
│                                           │ Confidence: 82%  │
│                                           │ 4032 × 3024 px   │
│                                           │                  │
│                                           │ [Run Detection]  │
│                                           │ [Edit Mask]      │
└───────────────────────────────────────────┴──────────────────┘

    Thumbnail tiles: color-coded bottom-right badge (H=red, M=peach, ✓=green, —=gray).
    Selected tile: 2px MAUVE border.
    QGraphicsView handles zoom (scroll wheel), pan (drag), overlay toggle (O key).

    Single mode¶

    Full-width QGraphicsView + Inspector panel. No thumbnail strip. For deep crack inspection.

    Compare mode¶

    QSplitter with two QGraphicsView instances (Original | Detected), zoom/pan synchronized via shared QTransform. For client reporting and annotation validation.

    5.2 Welcome view¶

    Shown when no project is loaded. Centered card with "New Project" and "Open Project" buttons (primary + secondary style). Recent projects list below.

    5.3 Other views¶

    Directory summary, file previews (JSON, text), device recommendation — follow the same content area pattern. Not redesigned in this phase beyond inheriting the new QSS.

    6. AI Chat Drawer¶

    A QWidget docked to the right edge of the main content area. Hidden by default; shown/hidden by ~ key or Cmd+/.

    Animation: QPropertyAnimation on maximumWidth (0 → 280px), 150ms ease-in-out. Feels like a panel sliding in, not a popup.

    Structure: 

    ┌──────────────────────────────┐
│ AI ASSISTANT      ~ to close │
├──────────────────────────────┤
│                              │
│  [user message bubble]       │
│        [assistant bubble]    │
│  [user message bubble]       │
│                              │
├──────────────────────────────┤
│ [Ask about this image…]  [↵] │
└──────────────────────────────┘

    • User bubbles: SURFACE0 background, right-aligned
    • Assistant bubbles: MAUVE/13% tint, left-aligned
    • Input: QLineEdit styled as SURFACE0, send on Enter
    • History: QScrollArea with auto-scroll to bottom on new message
    • Context: current file path injected into system prompt automatically

    Backend: No changes to services/ai_chat.py — the drawer is a new Qt widget wrapping the existing AIChatService.

    7. Status Bar¶

    Custom QStatusBar subclass. Always 24px tall, CRUST background, 1px SURFACE1 top border.

    Left: Green dot + project name (updates on project load/close)
    Center: Summary counts — N images · N critical · N medium (updates after detection runs)
    Right: App version string

    8. Implementation Sequence (Phase 0 scope)¶

    This spec covers the design language. The Phase 0 implementation delivers:

    1. QSS + theme.py — All tokens, master stylesheet, verified across all widgets
    2. App shell — Main window, title bar, menu bar, activity bar, QSplitter layout, status bar
    3. Explorer panel — File tree, context menu, project badge, new/open project actions
    4. Image viewer — Gallery+Detail mode with QGraphicsView, overlay toggle, Inspector panel
    5. AI chat drawer — Slide-in animation, chat UI wrapping existing AIChatService
    6. Welcome view — No-project state

    Remaining panels (Detect, Train, Active Learning, Settings) are Phase 1, built against the validated shell.

    9. Out of Scope¶

    • QML / Qt Quick (ruled out in feasibility spec)
    • Light mode (dark only for Phase 0; light mode support via alternate QSS in later phase)
    • Custom window chrome / frameless window (use native title bar)
    • New AI features or detection algorithms (visual design only)
    • Mobile / tablet form factors
