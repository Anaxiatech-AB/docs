    Database setup (Postgres + pgvector + PostGIS)¶

    Crackz stores project history, detections, and vector embeddings in Postgres. Two extensions are required or recommended:

    • pgvector (required) — stores and queries DINOv2 embedding vectors.
    • PostGIS (recommended) — enables geo find-near spatial queries. Without it crackz falls back to a Python Haversine path automatically.

    All three deployment paths below end at the same state:

    1. vector and postgis extensions enabled on the crackz database.
    2. CRACKZ_DATABASE_URL pointing at that database.
    3. crackz db init run to apply Alembic migrations.

    Minimum requirements¶

    Component Minimum
    Postgres 16+
    pgvector 0.8+ (required)
    PostGIS 3.4+ (recommended)

    pgvector 0.8+ is required because similarity search enables HNSW iterative scan (hnsw.iterative_scan), which keeps the result set at full size when a project/model filter is applied; that setting does not exist on earlier pgvector.

    CRACKZ_DATABASE_URL is the single configuration knob. Set it in the environment or in a .env file at the project root. The default value works out of the box with the Docker path below:

    CRACKZ_DATABASE_URL=postgresql+psycopg://crackz:crackz@localhost:5432/crackz

    Docker (dev / quickstart)¶

    The fastest path. A compose file is provided that runs Postgres 16 with both extensions pre-installed.

    # Start the database in the background
docker compose -f core/docker-compose.dev.yml up -d

# Apply migrations (no extra env needed — defaults match the compose file)
crackz db init

    The compose file builds a small local image (core/Dockerfile.postgres) that layers PostGIS onto the official, multi-arch pgvector/pgvector:pg16 image, so a single container provides both vector and postgis. crackz db init runs the migrations, which CREATE EXTENSION for both.

    To stop and remove the container (data is preserved in the named volume):

    docker compose -f core/docker-compose.dev.yml down

    To also drop the data volume:

    docker compose -f core/docker-compose.dev.yml down -v

    Bare metal (on-prem, e.g. foto-dator)¶

    Install Postgres 16, the pgvector extension package, and PostGIS for your distro, then create the database and role.

    Debian / Ubuntu¶

    # Add the PGDG repository if not already present
sudo apt-get install -y curl ca-certificates
sudo install -d /usr/share/postgresql-common/pgdg
curl -o /usr/share/postgresql-common/pgdg/apt.postgresql.org.asc \
     --fail https://www.postgresql.org/media/keys/ACCC4CF8.asc
# Follow https://wiki.postgresql.org/wiki/Apt for the full repo setup

sudo apt-get install -y postgresql-16 postgresql-16-pgvector postgis

    Create database and role¶

    -- Run as a Postgres superuser (e.g. sudo -u postgres psql)
CREATE ROLE crackz WITH LOGIN PASSWORD 'crackz';
CREATE DATABASE crackz OWNER crackz;

\c crackz

-- CREATE EXTENSION requires superuser unless the extension is trusted.
-- Run these as superuser, not as the crackz role.
CREATE EXTENSION IF NOT EXISTS vector;
CREATE EXTENSION IF NOT EXISTS postgis;

-- Grant schema usage to the application role
GRANT USAGE ON SCHEMA public TO crackz;

    Privilege note: CREATE EXTENSION normally requires superuser. Some managed Postgres distributions lower this bar; on plain bare-metal installs run the extension commands as the postgres superuser, not as the crackz application role.

    Configure and run migrations¶

    export CRACKZ_DATABASE_URL="postgresql+psycopg://crackz:crackz@localhost:5432/crackz"
crackz db init

    If you are importing history from an older SQLite project database, point the importer at the project (it reads that project's artifacts/project.db):

    crackz db migrate-sqlite --project path/to/project   # or --cfg path/to/project.yaml

    Hosted / managed (RDS, Cloud SQL, Supabase, Azure)¶

    Extension availability¶

    Provider pgvector PostGIS
    Amazon RDS for PostgreSQL Yes (>=15.2) Yes
    Google Cloud SQL for PostgreSQL Yes Yes
    Supabase Yes (built-in) Yes (built-in)
    Azure Database for PostgreSQL Flexible Server Yes Yes
    Neon Yes Varies by plan

    Check your provider's current docs — extension availability changes with product tiers and versions.

    Enable extensions¶

    Most managed providers expose a UI toggle or a single SQL command:

    -- Run once after creating the database
CREATE EXTENSION IF NOT EXISTS vector;
CREATE EXTENSION IF NOT EXISTS postgis;

    Some providers (e.g. Supabase) enable pgvector automatically — skip the CREATE EXTENSION vector step if it is already present.

    Set the connection URI¶

    Managed databases typically require TLS. Append ?sslmode=require (or sslmode=verify-full if you have a CA cert):

    export CRACKZ_DATABASE_URL="postgresql+psycopg://crackz:<password>@<host>:5432/crackz?sslmode=require"

    Then run migrations:

    crackz db init

    PostGIS-absent fallback¶

    If PostGIS is unavailable on your provider or disabled by policy, crackz still runs normally. The geo find-near command degrades gracefully to a Python Haversine calculation — slower for large datasets but functionally equivalent. No configuration change is needed; crackz detects the missing extension at startup.

    CLI reference¶

    Command Description
    crackz db init Run Alembic migrations to create or update the schema. Safe to run repeatedly.
    crackz db migrate-sqlite Import legacy project.db (SQLite) history into Postgres.

    Both commands are being added as part of the Postgres migration feature (issue #627). Run crackz db --help for up-to-date options.
