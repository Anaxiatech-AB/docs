    ADR-026: Text/Doc RAG over pgvector + Unified Retrieval Seam¶

    Status: Proposed

    Date: 2026-06-15

    Context¶

    crackz has two disjoint, partial retrieval surfaces:

    • Image similarity (semantic, server-side): defect_embeddings.embedding vector(768) (DINOv2-base, L2-normalized), HNSW cosine <=> filtered by project_id + model_name + embedding_version with hnsw.iterative_scan (core/src/crackz/db/repositories/embeddings.py).
    • Doc/chat search (keyword, not semantic, GUI-local): ADR-021 SQLite FTS5 over docs/*.md, chunked at ##, top-3 chunks injected into the Claude system prompt (gui/src/crackz_gui/services/ai_chat.py, gui/src/crackz_gui/data/{doc_chunker,chat_history_db}.py).

    There are no text embeddings anywhere yet, and FTS5 misses semantic synonyms (ADR-021 names this: "convergence" vs "loss not improving"). #665 asks whether to upgrade chat doc-search from keyword to semantic RAG now that pgvector exists in-tree (ADR-023). The complication is operational: core's pgvector needs a reachable Postgres and a text embedder, but the chat app is an offline-first desktop Qt app, and the import-linter forbids the GUI from importing crackz.cli and crackz.ai.* from importing crackz.cli. A decision is needed to pick the doc-RAG storage, embedder, and where it runs without breaking offline-first.

    Decision¶

    Build text/doc RAG on the existing pgvector substrate, behind a swappable retrieval seam, served as a core/server capability, with a hybrid desktop story that preserves offline-first.

    Storage — a separate doc_embeddings table (new Alembic migration 0004). Do not reuse defect_embeddings: it is image-specific (DINOv2-fixed dim; FKs to detection_result_id/detection_run_id; GPS/bbox/mask semantics). doc_embeddings mirrors the patterns (idempotent upsert, HNSW cosine, version columns), not the columns: - id, doc_path, header, chunk_index, chunk_text, model_name, embedding_version, dim, embedding vector(768), created_at; optional nullable project_id only if docs ever become project-scoped (default: global docs → none). - UNIQUE (doc_path, chunk_index, model_name, embedding_version) for idempotent re-index (mirrors the ON CONFLICT pattern in insert_embeddings). - HNSW vector_cosine_ops with the same hnsw.iterative_scan / ef_search tuning as search() in embeddings.py.

    Embedder — local Ollama (e.g. nomic-embed-text, 768-dim), reusing the local Ollama endpoint the GUI already talks to. This keeps doc-RAG offline-capable, adds no heavy in-app dependency, and fixes doc_embedding_dim = 768 (the same width as DINOv2 by coincidence — doc_embeddings remains a separate table because model and provenance differ). New settings: doc_embedding_model_name, doc_embedding_dim, doc_embedding_version in crackz_settings.py.

    Seam — a RetrievalBackend protocol shared by image and doc search, with a common SearchHit DTO. core/src/crackz/db/repositories/doc_embeddings.py mirrors embeddings.py (insert_doc_embeddings, search, rows_needing_embedding). A no-Typer doc-RAG function lives in embedding/service.py style.

    Serving — one FastAPI app, one GPU host, sharing inference and retrieval: POST /detect (wraps DetectionRunner, #643), POST /embed + POST /search (image), POST /rag (docs). All endpoints emit versioned JSON carrying model_version / embedding_version so federated callers pin compatibility.

    Desktop — hybrid (server-semantic + FTS5 offline). ai_chat.py's _get_context() selects a backend by availability: when a crackz retrieval service / Postgres is reachable, use pgvector doc-RAG (/rag); otherwise fall back to FTS5 (ADR-021), optionally with a small local Ollama rerank of FTS5 candidates. The GUI calls a core retrieval function or the HTTP service — never crackz.cli, never crackz.db directly — so import-linter contracts hold and the offline guarantee is preserved.

    Qdrant — contingency only. Stay on pgvector. Trip to Qdrant only on a measured trigger (recall/latency target unmet after ef_search/iterative_scan tuning; vector count outgrows one Postgres node; or a dedicated cross-app vector tier — which also implies an ADR-025 crossing). Because all vector access funnels through the repository / RetrievalBackend seam, adding Qdrant is a new backend implementing the same interface, selected by config, with no change to service.py, the endpoints, or callers.

    Consequences¶

    • Benefit: semantic doc/chat retrieval that beats FTS5 on synonyms, reusing the pgvector infra and versioning patterns already in-tree (no second vector DB, no ChromaDB — the originally-descoped #311–#315 stack).
    • Benefit: offline-first is preserved — the desktop degrades cleanly to FTS5 with no Postgres dependency; the heavy path is a server capability.
    • Benefit: one FastAPI app serves both survey_tool inference (#643) and retrieval; the embedder loads once on the GPU host.
    • Trade-off: semantic doc-RAG requires a reachable service/Postgres; full quality is not available purely offline. Accepted via the hybrid fallback.
    • Trade-off: a new table, migration, settings, and a text embedder to maintain, plus a re-index story for docs (parallels defect_embeddings embedding versioning).
    • Follow-up: build the FastAPI app (#643 Phase 1) and /rag (Phase 2); wire the GUI hybrid seam (Phase 3); revisit Qdrant only under a measured trigger (Phase 4).

    Alternatives Considered¶

    • Keep FTS5 only (ADR-021 status quo): cheapest, fully offline, but misses semantic synonyms. Rejected as the end state, kept as the offline fallback.
    • ChromaDB + sentence-transformers (the original #311–#315 RAG): +100MB deps, cold-start indexing, a Qt background thread. Rejected — disproportionate and redundant now that pgvector is the maintained substrate (this is why #311–#315 were descoped).
    • Reuse defect_embeddings for text: rejected — different dim, model, and provenance; image FKs and GPS/bbox/mask semantics do not apply to doc chunks; mixing fidelities in one HNSW index degrades ranking.
    • Hosted text-embedding API (OpenAI/Voyage): highest quality, smallest local footprint, but needs network + an API key and breaks offline-first. Rejected for the default; the seam leaves it available if a server-only deployment wants it.
    • Qdrant now: rejected — pgvector suffices at current scale; Qdrant is gated behind the swappable seam (ADR-025 invariant) for when a measured limit is hit.
